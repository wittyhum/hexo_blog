今日八股—ThreadLocal

Author: wuli韬 Date: August 9, 2025  17:20:39 Category: 学习日记

ThreadLocal

ThreadLocal是什么

ThreadLocal 是一种用于实现线程局部变量的工具类。它允许每个线程都拥有自己的独立副本，从而实现线程隔离。

在 Web 应用中，可以使用 ThreadLocal 存储用户会话信息，这样每个线程在处理用户请求时都能方便地访问当前用户的会话信息。

在数据库操作中，可以使用 ThreadLocal 存储数据库连接对象，每个线程有自己独立的数据库连接，从而避免了多线程竞争同一数据库连接的问题。

在格式化操作中，例如日期格式化，可以使用 ThreadLocal 存储 SimpleDateFormat 实例，避免多线程共享同一实例导致的线程安全问题。

ThreadLocal优点：每个线程访问的变量副本都是独立的，避免了共享变量引起的线程安全问题。由于 ThreadLocal 实现了变量的线程独占，使得变量不需要同步处理，因此能够避免资源竞争。

缺点：ThreadLocal 的内存消耗较大，因为每个线程都存储了一个变量副本，如果变量非常大，那么 ThreadLocal 的内存消耗可能会非常大。另外，ThreadLocal 的变量不能被垃圾回收器回收，因此需要手动清理 ThreadLocal 的变量。

ThreadLocal的在项目中的使用

在项目中，登录后的用户每次访问接口，都会在请求头中携带一个 token，在控制层可以根据这个 token，解析出用户的基本信息。假如在服务层和持久层也要用到用户信息，就可以在控制层拦截请求把用户信息存入 ThreadLocal。这样在任何一个地方，都可以取出 ThreadLocal 中存的用户信息。

ThreadLocal的实现

当我们创建一个 ThreadLocal 对象并调用 set 方法时，其实是在当前线程中初始化了一个 ThreadLocalMap。

ThreadLocalMap 是 ThreadLocal 的一个静态内部类，它内部维护了一个 Entry 数组，key 是 ThreadLocal 对象，value 是线程的局部变量，这样就相当于为每个线程维护了一个变量副本。

Entry 继承了 WeakReference，它限定了 key 是一个弱引用，弱引用的好处是当内存不足时，JVM 会回收 ThreadLocal 对象，并且将其对应的 Entry.value 设置为 null，这样可以在很大程度上避免内存泄漏。

弱引用与强引用

首先是强引用，比如 User user = new User("wuli韬"); ，user就是一个强引用，new User("wuli韬") 就是强引用对象。

当 user 被置为 null 时，对象就会被垃圾回收；否则即便是内存空间不足，JVM 也不会回收这个强引用对象，宁愿抛出 OutOfMemoryError。

而弱引用，Entry 的 key 就是一个弱引用对象。

ThreadLocal的内存泄露

ThreadLocalMap 的 Key 是 弱引用，但 Value 是强引用。

如果一个线程一直在运行，并且 value 一直指向某个强引用对象，那么这个对象就不会被回收，从而导致内存泄漏。

解决的方法就是在使用完Threadlocal后，手动调用remove()方法释放内存空间。

remove() 会调用 ThreadLocalMap 的 remove 方法遍历哈希表，找到 key 等于当前 ThreadLocal 的 Entry，找到后会调用 Entry 的 clear 方法，将 Entry 的 value 设置为 null。

然后执行 expungeStaleEntry() 方法，清除 key 为 null 的 Entry。

ThreadLocalMap解决哈希冲突

如果计算得到的槽位 i 已经被占用，ThreadLocalMap 会采用开放地址法中的线性探测来寻找下一个空闲槽位：

如果 i 位置被占用，尝试 i+1。

如果 i+1 也被占用，继续探测 i+2，直到找到一个空位。

如果到达数组末尾，则回到数组头部，继续寻找空位。

不使用HashMap的拉链法是因为ThreadLocalMap 设计的目的是存储线程私有数据，不会有大量的 Key，所以采用线性探测更节省空间。
拉链法还需要单独维护一个链表，甚至红黑树，不适合 ThreadLocal 这种场景。

ThreadLocalMap扩容机制

ThreadLocalMap 采用的是“先清理再扩容”的策略，不会直接在元素数量达到阈值时立即扩容，而是先清理被 GC 回收的 key，然后在填充率达到四分之三时进行扩容。扩容时，数组长度翻倍，并重新计算索引，如果发生哈希冲突，采用线性探测法来解决。
